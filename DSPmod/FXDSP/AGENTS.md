# FXDSP 工作约定

- 用户明确要求后续工作停止使用子智能体。所有实现、研究、检查和整合由当前主智能体完成，不创建或调用子智能体；只有用户之后明确恢复才可改变。
- 不同物品市场不可互换本金或收益。同类物品的合法交易获利、复投和替代产线是允许且鼓励的玩法，不添加保护产线的收益硬上限。
- 当前方向为物品本位的保证金合约：铜矿直接作为余额、保证金与盈亏单位，1 个实体铜矿存入形成 1 铜余额；交易标的是模拟指数，避免把铜对自身的固定兑换关系做成浮动价格。
- 优先支持保持游戏打开后 F6 更新。涉及存档格式时必须兼容旧快照与同会话交接，不清空旧账户；新增依赖或原型注册才考虑完整重启。
- UI 复用原版视觉资产时，不复用发光/HDR 字体或按钮材质；保持文字与背景对比度。
- 界面采用红涨绿跌；每 1 游戏秒跳价并绘制一根美术 K 线，随机上下影线只影响展示，不影响成交、盈亏或强平。比例开仓须预留费用以支持 100% 下单，杠杆范围为 1～100×整数；存入/提取输入独立。
- 用户要求后续游戏界面只展示玩家需要的信息：操作、资产、价格、持仓和风险。不要添加刷新周期、配色解释、模拟/原型/开发说明等工程文案；实现细节保存在文档与日志。
- 当前市场扩展为铜矿、塑料、电磁矩阵，各自账户、行情和持仓独立，本金与收益不得跨物品转换。
- 用户已明确新增建筑币作为例外：它可按固定比例双向兑换建筑、地基、物流运输单位及五种战斗单位，并有独立交易行情；不与资源/矩阵账户互换。矩阵市场扩展到六种矩阵，按资源/矩阵/建筑币分类。
- 0.7 显示标题改为“DSP 交易平台”，保留 FXDSP 工程名、DLL、GUID 和存档身份。界面使用“累计盈亏”“当前持仓”“平仓”；建筑币不显示借用的原版物品图标。
- 全部持仓页与右上角持仓面板按物品分别显示浮动盈亏，不将不同币种直接相加。右上角仅支持隐藏恢复、逐项平仓和跳转详情，不再提供展开/收起；常规刷新不先禁用再启用按钮。
- 右上角持仓面板须保持紧凑：标题“持仓”、每行仅品种图标/浮动盈亏/平仓，紧凑单行布局，详情入口为“详情”；建筑币继续用“币”文字，不能借用地基图标。行情扩展前先读 docs/market-performance-0.7.1.md，区分本地压力测量与实际 Unity 性能。
- 资源可在左侧“选择资源”页按需启用。未选资源不创建行情账户，停用的既有资源不推进报价/时间/RNG；余额和历史仍保存，重新启用不得补算停用期间行情。有持仓时必须先平仓才能停用。选择状态随存档/F6 保存，矩阵与建筑币沿用原运行方式。

- 0.9 起入口为并列的“原料、材料、武器、消耗品、矩阵、建筑币”，前四类继续各自按需启用。金额与盈亏只显示两位小数，不改底层精度；行情价保留四位，数量/杠杆保持整数。HUD 平仓按钮须足够宽且标签不换行，避免显示超出点击区域。

- 交付库存不设玩法容量上限；用 BigInteger 扩展库存与安全原版运输缓存守恒，不能直接把原版 int 容量拉满导致溢出。主界面仅显示总量/操作，缓存工程细节仅入开发文档。
