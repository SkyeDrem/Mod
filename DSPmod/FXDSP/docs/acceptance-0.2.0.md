# FXDSP 0.2.0 游戏验收

本版本是一个铜矿现货市场的纵向原型。已实现游戏内窗口、背包入库/提取、独立结算、模拟行情、游戏存档和 F6 交接。交易科技、其它物品、专用箱/塔留待下一阶段。

## 开始

1. 完整退出游戏，再用 r2modman 的 `test2` Profile 启动 Modded。
2. 本次部署会启用 ScriptEngine 的 `LoadOnStart=true`，FXDSP 在读档前自动加载，首次无需按 F6。
3. 进入一个测试存档，准备至少 100 个**未喷涂铜矿**。可先另存一个测试副本。
4. 按 **F8** 打开或关闭平台。快捷键也可在 ConfigurationManager 中修改。

初始平台库存与结算额度都为零，没有测试赠款。结算额度只属于铜矿市场。单次数量输入支持 9 位正整数，这是界面输入范围，不是资产或收益上限。

## 操作验收

| 操作 | 预期 |
| --- | --- |
| 输入 100，点击“从背包存入铜矿” | 背包减少 100，平台实物增加 100，结算额度仍为 0。 |
| 输入 50，点击“卖出铜矿” | 平台实物减少 50，额度按当时卖出价扣 1% 费用后增加。 |
| 输入 10，点击“买入铜矿” | 平台实物增加 10，额度按当时买入价与 1% 费用扣除。 |
| 输入 10，点击“提取铜矿到背包” | 背包增加 10，平台实物减少 10，不再按行情扣一次钱。 |
| 输入过大、0、负数或空值 | 操作禁用或明确拒绝；两侧资产不因失败发生变化。 |
| 背包满时提取 | 未接收部分仍留在平台，不丢到地上；有部分容量就只转移实际接收量。 |

上述即时买卖用于验证扣账，因价差与费用通常亏损；获利需要等到有利行情。界面预览是估算，点击时按最新可执行报价成交。

## 行情和窗口

- 约每 **5 个游戏秒**更新报价，图表保存最近 120 个采样；低 UPS 时按游戏逻辑时间推进。
- 暂停时行情和交易停止。关闭窗口后行情仍随游戏运行，UI 不继续绘制。
- 检查字体、背景、铜矿图标和图表是否显示；拖动标题栏，调整游戏 UI 缩放。
- 数量框输入时，数字不应触发建造热键；鼠标操作窗口不应点到地面。
- ESC 优先结束数量输入，再关闭平台，不应一次同时关闭窗口并打开其它菜单。

## 保存和 F6

1. 记录平台实物、额度和背包数量，保存游戏。
2. 回到主菜单，重新读入刚才存档，再按 F8：资金和库存应与保存时一致。
3. 在游戏中按 F6，窗口会随旧实例销毁；再按 F8，账户应继续保留，行情不应重抽。
4. 连续多次 F6 后，按钮不应一次执行多笔；再保存、退出、重新启动和读档复核。
5. 读取另一份没有 FXDSP 数据的存档，应得到该存档自己的零账户，不能带入上一档资金。

FXDSP 使用 DSPModSave 的 `.moddsv` 旁档；移动/备份游戏存档时应一起保留。世界或保存 tick 不匹配时停止交易并显示原因。首次在已入档后才加载、且没有账户导入或交接时，会要求重新读档，并暂挂保存以免覆盖未读取的旧账户；本次完整重启并自动加载的流程可以避免这一情况。

此检测不是跨文件原子事务，也不能识别同世界同 tick 的所有不同存档分支。缺失旁档按 DSPModSave 的约定视为新账户，不应通过删除旁档恢复资金。

## 当前边界与反馈

- 仅铜矿市场；不支持跨物品兑换、杠杆、卖空、限价单或自动交付建筑。
- 不设置 NPC 库存、补货或净收益配额，允许正常交易获利和复投。
- 为避免静默损失/复制增产点，首版背包中存在喷涂铜矿时拒绝入库；新购物品提取时不带增产点。
- 源码与逻辑检查已通过，实际 UI 层级、字体、输入、背包和存档仍需要本轮游戏验收。

遇到异常时，记录操作与大致时间；日志位于测试 Profile 的 `BepInEx/LogOutput.log`，画面问题可附截图。成功加载应出现 `FXDSP 0.2.0 loaded`、`FXDSP save handler registered`，读档后会记录账户初始化或导入状态。
