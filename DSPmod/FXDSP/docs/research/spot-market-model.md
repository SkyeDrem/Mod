# FXDSP 现货市场模型研究与设计建议

研究日期：2026-10-25。范围是玩法与架构研究，本文件不代表已实现功能，也不确定首批交易物品名单。文中“现实机制”有一手来源；“FXDSP 建议”是针对工厂游戏的设计判断。

## 1. 对当前构想的判断

**方案可行，建议采用“分物品隔离结算的现货平台”，而不是严格固定汇率的物品币。**

每个市场只允许一种原版物品进入和离开；账户里的结算额度只能用于这个市场，不能转账到其他物品市场。这保留了“铜市场只能赚回铜，不能换矩阵”的核心约束。玩家必须先拿到该物品，再承担卖出后价格变化和回购数量变化的风险。

这里的交易对象是游戏商品，整体更接近商品现货交易，而不是现实外汇交易。FXDSP 可以保留为项目名称；面向玩家的功能名称建议用“物资交易平台”或“现货交易”，不必把所有界面都包装成外汇。

**用户已明确：隔离限制跨物品兑换，同类物品获利和替代产线则属于鼓励的玩法。**玩家取得高级物品后，可以靠交易持续增加它的数量，不需要为了保护该产线设置 NPC 库存、补货或提现硬上限。费用、深度、科技与交付的细节仍需分别设计，不能把产线替代当作漏洞。

## 2. 现实机制中值得借鉴的部分

| 现实机制 | 研究结果 | FXDSP 可借鉴的内容 |
| --- | --- | --- |
| 现货与未来合约 | CFTC 将现货与当前支付、交付相联系；未来合约则约定未来履约。[CFTC 术语表](https://www.cftc.gov/LearnAndProtect/AdvisoriesAndArticles/CFTCGlossary/index.htm) | 首版交易成交时即确认货权，不加入到期日、杠杆、保证金或强平。 |
| 仓单 | CFTC 对仓单的说明强调它是已存放商品的凭证。[同一术语表的 Warehouse Receipt 条目](https://www.cftc.gov/LearnAndProtect/AdvisoriesAndArticles/CFTCGlossary/index.htm) | “库内物品数量”可以按数量提货；它与买卖时使用的结算额度分开。 |
| 余额与冻结 | 交易所要求足够的可用资产覆盖订单和费用，未完成订单会占用余额。[Coinbase 交易规则，1.2、5](https://www.coinbase.com/legal/trading_rules) | 分开显示可用、冻结和总额，避免同一份物品同时被卖出和交付。 |
| 成交与结算 | 成交可以分多笔，已成交部分会更新双方账户；挂单不等于成交。[Coinbase 交易规则，1.7、1.8](https://www.coinbase.com/legal/trading_rules) | UI 的“下单”“已成交”“待交付”“已入箱”需要是不同状态。 |
| 买卖价与深度 | 买价、卖价之间存在价差，深度表示不同价格可承接的数量。[Kraken 交易术语](https://support.kraken.com/articles/115000364388-trading-glossary) | 显示玩家实际能卖出的报价和实际能买入的报价，不只显示一根曲线。 |
| 市价与限价 | 市价单获取当时可用报价，可能分价格成交；限价控制可接受价格，可能不能成交。[Coinbase 订单说明](https://help.coinbase.com/en/coinbase/trading-and-funding/advanced-trade/order-types) | 首版先做明确数量的即时买卖；后续再做限价单。 |

这些资料用于理解系统职责，不照搬现实交易所的收费标准、限额、交易对或监管要求。FXDSP 是单人游戏规则，首版可让一个模拟 NPC 做市方提供报价，不必搭建真实玩家撮合交易所。

## 3. 为什么严格 1:1 锚定会产生问题

假设“1 铜币随时无条件换 1 铜矿，1 铜矿也随时换 1 铜币”。在这种设定下，铜矿用铜币计价的合理兑换关系已经约等于 1，不适合再独立生成长期偏离 1 的行情。

如果同时再开放动态买卖，就出现第二条兑换通道。例如市场愿意用 2 铜币买 1 铜矿，玩家先从固定通道用 1 铜币提取铜矿，再卖给市场得到 2 铜币，可以不等待行情变化而循环增加余额。反过来，若市场以 0.5 铜币卖铜矿，买入后在固定通道兑换也会增加铜币。手续费只能缩小漏洞区间，不能解决模型冲突。

这不是“每种物品独立账户”不可行，而是把两个不同概念都叫作物品币：

| 概念 | 代表什么 | 提取规则 |
| --- | --- | --- |
| **物品库存 / 仓单** | 平台托管、归玩家所有的实际物品数量 | 1 个库存单位提取 1 个同种物品。仅改变位置，不经过行情兑换。 |
| **市场结算额度** | 卖出该物品获得的、仅在此市场使用的购买力 | 按当时可执行卖价买回物品，数量可能增减；不存在额外固定兑换入口。 |

结算额度不必创建成背包里的新物品。首版把它作为账户数字更简单，也避免实体币进入分拣器、物流塔或被其他配方引用而打开跨市场通道。

UI 可以使用“铜矿结算额度”“塑料结算额度”等名称；不要把两者合并为一个可转移的总钱包。“总资产”如需展示，只能是信息汇总，不具备兑换功能。

## 4. 一次完整交易示例

以下费率和行情只用于说明规则，不是建议采用的最终平衡数值。假设两个报价都已有足够深度，费用用该市场结算额度支付。

1. 玩家向平台实际交入 **100 铜矿**。铜矿库存增加 100，结算额度仍为 0；这是入库，不是卖出。
2. 当前可卖报价为 **1.00 额度 / 铜矿**。卖出这 100 个库存，交易额 100，收取 1% 手续费 1，余额变为 **99 额度**，玩家铜矿库存变为 0。
3. 之后可买报价降到 **0.80 额度 / 铜矿**。买回 122 铜矿，货款为 97.60，1% 费用为 0.976，总支出 **98.576**，剩 **0.424 额度**。
4. 平台归玩家所有的铜矿库存为 122。玩家申请提取并成功交付 **122 铜矿**，与最初投入相比，实际拿到的铜矿净增加 **22 个**。
5. 剩余 0.424 只能留在铜矿市场。它不能买塑料、矩阵，也不能以固定汇率换铜矿。

若回购价格上涨，99 额度可能只能买回少于 100 铜矿；持有结算额度并不等于保本。首版没有负余额，也没有强平：损失表现为回购数量变少或等待期间缺少实物。

玩家本来拥有铜矿，卖出后等待回购，不属于允许无物品卖出的裸卖空。界面用“买入 / 卖出”就足够，不必沿用上一轮外汇方案里的“开仓、保证金、爆仓”。

## 5. 最小账本与不可破坏的约束

以 `marketId` 作为市场主键，映射到明确的 `itemId`。首版可以一物品一市场；不要把游戏物品名称作为存档键。

| 状态 | 含义 |
| --- | --- |
| `AvailableItemQuantity` | 已归玩家所有、尚未卖出或预留交付的库存 |
| `ReservedItemQuantity` | 被挂单等操作占用的库存；首版未做挂单时可为 0 |
| `AvailableSettlementUnits` | 当前市场可用于买入的额度 |
| `ReservedSettlementUnits` | 订单预留购买力及必要费用 |
| `PendingDeliveryQuantity` | 已从可用库存转出的待交付物品 |
| `NpcStock`（可选） | 仅在另行选择有限库存玩法时使用；不是基础账本或产量约束 |
| `CumulativeDeposits / CumulativeDelivered` | 从游戏世界入库和实际交回游戏世界的累计数量 |

建议维护以下不变量：

- 每一条交易指令都携带 `marketId`，额度从不跨市场扣划。
- 玩家没有免费初始额度。新增市场的物品本金来自其真实入库；解锁费用与交易本金分开记账。
- 物品数量为整数，不能因小数舍入铸造实物；额度和费用使用确定精度的整数单位或十进制规则。
- 卖出数量不超过可用物品，买入支出连同费用不超过可用额度，所有余额非负。
- 下单时的报价预览不是成交凭证。后台重新校验报价版本、数量、市场容量和可用资产。
- 买入成交时，玩家库存增加与额度扣除在同一原子操作中完成；若另行启用有限 NPC 库存，再同步扣减对应库存。交付仅转移这批已经取得货权的物品，不重新扣一次货款。
- 一份数量在“可用库存、订单冻结、待交付、已交付”之间迁移，不同时记在两处。
- 统一记录单调递增交易编号；重复提交和重载恢复不得二次结算。

平台的虚拟库存在这里是 Mod 自己保存的托管数量，不代表把真实物品偷偷保留在原箱子里。入库成功后，原箱子/背包必须实际扣除相应数量；失败则整笔不记入账本。

## 6. 架构建议：共用引擎，配置多个独立市场

不需要为每一种商品写一套行情和交易代码。建议使用五个职责层：

1. **市场定义**：物品 ID、前置条件、最低数量、报价精度、费用和波动参数；深度、库存与补货仅作为可选扩展，不是保护产线的默认限制。首批物品名单留待后续规划。
2. **行情与报价**：共用时间推进、趋势/震荡/事件逻辑；每市场独立状态和随机流，输出可执行的 bid / ask / depth。
3. **订单与账本**：检查权限、余额和数量，冻结资产，生成成交记录与费用，提交结算。这里不直接调用 Unity UI 或箱子 API。
4. **物品托管与交付**：负责从背包/箱子/塔入库、排队提货、实际插入数量，以及拆除、满箱和切档处理。具体 DSP 接口由游戏适配层封装。
5. **进度与持久化**：记录认证、市场解锁、净交付指标、存档版本、随机数状态和未完成命令。UI 仅显示这些服务的快照并提交命令。

可抽象为 `MarketDefinition → MarketState → Quote/TradeService → Ledger → DeliveryService`；技术上可以仍在同一个 Mod DLL 内，逻辑边界清晰即可。

首版建议做模拟报价方的双边报价，允许按已定义的成交规则取得同类物品；不必先构建有限 NPC 总仓、完整订单簿或真实联网行情。有限深度是否加入，由交易体验决定，不能预设为限制玩家长期收益的上限。

## 7. 行情与成交规则

### 7.1 共用行情引擎

行情可由慢变需求中心、短期随机波动和少量事件组成。每个市场配置波动、回归速度、事件权重和流动性差异；不要为每个物品手写几百根 K 线。

建议按固定游戏逻辑时间间隔推进，暂停时停止，退出游戏后不推进。保存价格状态、事件状态、逻辑时间和随机数状态；读档或 F6 不重新摇一套价格。玩家可以主动存读档，不必把首版变成反作弊系统，但不能因普通保存或热重载意外改变账本与行情。

行情不能总是立即回到公开的固定中心，否则会形成容易重复的机械策略；也不应只用完全独立白噪声，让玩家没有观察和计划的依据。这是游戏性取舍，不是对现实价格可预测性的承诺。

### 7.2 成交以可执行报价为准

- 显示“当前买入价、当前卖出价、费用、预计到手数量”，中间价或最后成交价仅作参考。
- 大单可以分档报价、部分成交，或者在首版明确提示容量不足并限制一次可成交数量。
- 若加入限价单，价格触及只是必要条件之一，还要检查可成交容量；订单只在成交部分结算，余量保持冻结或按规则取消。
- 对输入数量设置整数范围、上限与溢出检查；保留很小的可用额度余额，而不是自动当作费用清零。
- 舍入规则必须让拆成许多小单不能减少总费用或多得到物品。建议以明确的成交聚合规则计算费用，并在最小精度处向收费方保守取整。

玩家交易也影响价格时，要用完整的深度/库存曲线计算实际平均成交价，不能简单地“按旧价买入 → 抬高显示价 → 按新价全量卖出”。同一外部状态下的即时闭环买卖应因价差和费用而亏损，而不是凭自己推动行情获利。

## 8. 用户确认的收益目标与交易正确性

### 8.1 允许交易成为同类物品的替代生产路线

铜不能换矩阵，是用户要求的资产边界。玩家通过塑料市场把少量塑料交易成大量塑料，是用户明确推荐的玩法；技术足够好时，可以用市场替代塑料产线。

本节撤回此前以保护产线为目的提出的默认库存和补货限制，采用以下方向：

| 规则 | 目的 | 当前定位 |
| --- | --- | --- |
| **分物品结算** | 铁矿获利不能支付白糖或其它物品 | 核心约束。 |
| **本金复投与合法增长** | 允许交易技巧成为资源来源乃至产线替代 | 明确支持，不用产量配额限制。 |
| **价差、费用、可选深度** | 提供下单成本、风险和策略选择 | 参数待定；不以压低净供给、保护工厂产线为目的。 |
| **账本与订单正确性** | 阻止复制、重复结算、舍入和即时报价漏洞 | 必须验证；与允许正常交易获利不冲突。 |

模拟报价方可以按规则持续提供物资，不要求其供货量追溯到有限初始库存和补货预算。玩家货权仍必须来自实际入库或成功成交；成功买入导致的合法物资增长，与同一请求重复入账是两回事。

交付耗电、吞吐和物流规则用于决定如何接入工厂；不承担阻止市场替代产线的职责。具体设置仍待用户后续选择。

如果以后希望有有限库存、补货或特殊市场事件，应作为单独玩法提出，而不是恢复为未经用户确认的全局收益硬上限。首版重点验证跨物品隔离、大额交易、长期复投与正常亏损风险。

### 8.2 必须区分合法获利与实现漏洞

| 情形 | 预期结果 |
| --- | --- |
| 直接入库后马上提取 | 只改变位置，不创造盈利。 |
| 同时刻卖出再买入 | 因价差/费用净损失，不能无风险增殖。 |
| 同时刻买入再卖出并影响报价 | 仍不能靠自己推动行情创造正收益。 |
| 一大单拆成很多小单 | 费用和精度规则一致，不能靠舍入制造收益；若另行启用深度，执行其明示规则。 |
| 合法交易持续获利并复投 | 允许同类物品增长，规模可达到替代产线；不能误判为复制漏洞或自动封顶。 |
| 反复转入/提取、拆装交付站、F6 | 不重复奖励、不重抽行情、不返还已花本金。 |
| 退出再进、切到另一存档 | 行情、容量、认证、资产各属于正确存档，不串档。 |
| 增产物品入库后提现 | 不能因托管往返免费增加增产点数；原样保留或明确处理的规则须单独决定。 |

## 9. 解锁与“上一市场盈利开下一市场”

“提交 100 铜矿解锁系统”“提交 100 塑料开塑料市场”在结构上可行。建议区分三个状态：

- **原版技术可用**：尊重科技树的硬性前置。
- **市场认证完成**：交付该市场要求的真实物品样本或认证材料，消耗与否明确说明。
- **市场运营等级**：由交易表现解锁更高额度、更多订单类型或交付能力。

认证消耗单独记录为进度成本，不记成卖出成交、交易入库本金或交易盈利。解锁后也不自动发放同额可交易额度；否则认证过程会悄悄变成首次充值或免费本金来源。

推荐解锁逻辑为：

```text
原版科技前置满足
AND 该物品的实体样本/认证满足
AND 认证成本条件满足（可由上一市场成就减免）
```

“提前”可指提前开放申请、降低认证消耗，或者提高最初的流动性等级；不建议跳过原版科技前置、免费送下一物品，也不让铜市场结算额度支付塑料本金。这样交易技巧能缩短等待，又不直接把资源链打通。

如果用户更偏好强烈的跳级奖励，也可允许利润成就把“100 个样本”降低成较少样本；样本和科技门槛的具体强度由用户决定，不以保护持续产线或限制同类收益为理由额外加码。

### 利润统计建议

不要把成交额、卖出回款、充值、浮盈，或“只累计盈利单而不计亏损”当作解锁进度。它们都可能让玩家刷循环，或让入库本金被当成收益。

首版可以使用最容易解释的**实际净提取增量**：

```text
某市场已到手净增量 = 累计实际交付到游戏世界的数量 − 累计从游戏世界实际入库的数量
```

这是平台对世界的净实物流出量，不等同于现实财务报表里的已实现货币利润。它不包含尚未交付的库存、额度或浮动估值；因此会较保守，需要先取回本金才能变为正值。若玩家取回 122、初始交入 100，则为 +22；把这 122 再存入并原样取回，累计净增量不会进一步增加。

这些累计量只统计实际完成的交易托管出入库，不含认证消耗、赠品、调试资金或其他 Mod 发放的奖励。不同物品的净增量单位不同，不直接相加成全平台通用“利润点”。

解锁判断可以记录此指标达到的历史最高水位，已经解锁的权限不反复撤销；但不能把每次提取的正差独立累加。若以后需要以“交易技巧”而非净补给评估成绩，再加入现金流调整后的权益或成本批次模型，同时区分已实现与未实现结果。

## 10. 交付与现货结算怎样兼容

“成交即获得物品所有权，实际运入箱子/塔需要时间”是清晰的分层：玩家看到库存已经到账，但物理交付队列继续工作。不要把物流延迟误做成合约到期风险。

交付数量以游戏容器实际接收的数量确认；容器满时保持在待交付库存，暂停并显示原因。拆除、改槽位、星球切换或读档后找不到目标时，不销毁物品，也不再次退款；应暂停并允许重绑目标或取消回到可用库存。每次插入与扣减台账需要在正确游戏线程/模拟时机作为一致操作完成。

开始绑定原版箱/塔、后续克隆专用建筑，是游戏适配层的实现选择，具体参考另见 DSP 科技与交付研究。本模型不要求首版增加实体币或新的原料链。

## 11. 与替代方案比较

| 方案 | 对“铁换矩阵”的控制 | 体验与开发取舍 |
| --- | --- | --- |
| **分物品隔离额度（推荐）** | 结构上禁止跨物品购买 | 钱包较多，但同一引擎可共用；最符合用户当前原则。 |
| 通用货币 + 科技门槛 + 购买额度 | 能防未解锁矩阵，但解锁后仍允许低阶材料补贴高阶物品 | 界面简单，跨物品贸易更丰富；不能声称与严格隔离等价。 |
| 通用货币 + 每种物品独立交付资格/额度 | 跨物品购买被数量预算限制 | 需要解释资格、货币、库存三重限制，规则可能更复杂。 |
| 仅同品种存入/取出的收益账户 | 禁止跨物品兑换 | UI 更短，但如果收益自动发放，会弱化主动交易，需要另定收益来源。 |
| 纯模拟交易分数，实物奖励为有限订单 | 通过奖励物品白名单和限额限制 | 最容易隔离风险，但交易与真实资源的联系较弱。 |

若未来想要有限跨资源贸易，可以作为可选模式或后期系统另行设计。不要在首版悄悄加通用结算账户，削弱已经承诺的隔离边界。

## 12. 分期与需要用户决定的事项

推荐顺序：

1. **规则原型**：在独立核心逻辑中实现一个抽象物品市场、整数账本、即时买卖和费用，支持长期复投；用上述例子和漏洞列表验证。不先确定完整物品名单。
2. **游戏内闭环**：一个市场、少量真实物品入库和提取、原版风格窗口、保存和 F6 状态规则。
3. **解锁与物理交付**：市场认证、专用科技入口、箱/塔交付、暂停与重绑。
4. **内容与运营扩展**：选定重点物品、各自参数和事件、限价单和市场等级；再评估自动交易或多市场内容。

后续应由用户明确的几个选择：

- 是否确认“额度不可跨市场、没有固定兑换通道”作为基础规则。
- 实体样本是消耗型认证费用，还是暂存验收后返还；它与交易本金不能混为一项。
- 上一市场的盈利只减免费用，还是允许减少下一市场所需的样本数量。
- 用户已经确认可通过交易替代同类产线；后续确定行情风险、操作节奏、费用和是否加入深度，不再把“收益只能补缺口”当作默认目标。
- 是否处理已喷涂物品，以及入库/提取时如何保留或消耗增产点数。
