# 1.1.0 行情随机数更新

## 行为

- 新建世界的初始市场、首次选择的其它市场：使用系统 `RandomNumberGenerator` 生成非零种子，不再由物品 ID 固定生成。
- 真实读档：世界标识和保存 tick 校验通过后，为所有已保存市场重新播种，保证新种子不同于该市场存档中的种子。停用市场也同步更新导出缓存，不产生新报价。
- 同一会话 F6：恢复种子并继续原随机序列，不重新播种。读档之后立即 F6 也遵守此规则。
- 暂停、切换界面、启停已有市场：仍按原有规则暂停或继续，不重新播种、不补算停用期间行情。
- 错误、损坏或不匹配的存档仍走原有锁定路径，不能因读档失败重新建立零余额账户。

## 保持的机制

仍由 Xorshift32 逐根生成 [-1, 1] 噪声，保留原公式：

```text
momentum = momentum × 0.88 + noise × 0.0024
nextPrice = price + (1 - price) × 0.006
            + price × (momentum + noise × 0.008)
```

每 60 游戏 tick 报价一次，价格范围 0.2～5。读档时价格、趋势动量、历史、持仓、余额、费用、成就及物流库存照常恢复；只改变后续噪声序列。系统随机源只用于创建或读档播种，不逐帧或逐报价调用。

存档字段及格式版本均不改变，1.0.0 存档仍可读取。普通二进制 Import 本身保持精确恢复，读档重新播种由 MarketSession 在校验后单独执行，因此不会影响 F6。

这会阻止记住固定走势后通过 SL 重演，但不阻止反复读档尝试不同未来。因保留趋势动量，刚读档后的走势仍可能相似，单根 K 线方向也可能偶然相同。

## 本轮验证

仅检查受影响部分：

- Core：14 项通过，含原公式推进、分步/批量一致性、边界和精确序列恢复。
- Margin：55 项通过，含杠杆、强平、K 线和启停市场不补算。
- Persistence：31 项通过，含重复读取同一快照后未来价格分歧、现有账户除随机种子外逐字节不变、F6 继续读档后的行情分支、停用市场缓存保留新种子、延迟载入和异常存档锁定。
- 两个 1.1.0 Release 模块构建通过，0 警告、0 错误。

以上为初步迭代的相关检查。用户随后要求完整检查并推送 GitHub，完整结果见 [1.1.0 发布检查](audit-1.1.0.md)。仍未进行实际游戏冷启动或手动 SL 验收。

## 游戏验收

1. 更新 1.1.0 发布包并重启游戏，读取原存档，检查价格、余额和持仓保持。
2. 保存后观察十余根 K 线，再读同一存档，确认后续走势发生分歧；不要求首根必定反向。
3. ScriptEngine 开发模式下按 F6，确认当前价格和持仓连续，后续行情不因热重载重新播种。
