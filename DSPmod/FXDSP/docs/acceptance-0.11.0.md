# 0.11.0 交付平台验收

本版新增三种建筑原型及 LDBTool 3.0.3 依赖。**本次必须保存后退出游戏，再从 r2modman 的 FXDSP 配置启动并读档**。F6 只能更新交易逻辑，不能代替本次首次原型注册。后续普通交易/UI 调整仍可 F6。

## 进入与建造

1. F8 打开平台，检查自演化研究站位于四级兑换；建筑币左栏的行情交易按钮加高，与兑换组留有间隔。右上角持仓面板“详情”左边应有“兑换”，直接打开建筑币兑换页。
2. 进入顶部“交付平台”，背包准备对应的原版建筑，点击改造按钮；每座消耗 1 座小型储物仓 / 行星物流运输站 / 星际物流运输站，得到小型交付平台 / 行星级交付平台 / 星际交付平台。建筑币兑换页也包含三种新平台。
3. 从背包建造平台，再回到交付平台页绑定。整个交易系统同时只能绑定一座；已有绑定时其它绑定按钮禁用，必须先解除再换绑。绑定与库存随存档和 F6 保存。

## 存取与运输

- 交易市场底部的来源可选“背包”或“交付平台”；可用数量应随实时库存刷新。先存入平台，再向账户存入，确认平台扣物、账户增额；从账户提取时方向相反。
- 打开市场后，用原版建筑界面取走物品，再回市场点击存入旧数量，应拒绝或只记实际移出量；不得生成额外余额。
- 小型平台只有一个物品槽。有库存时不能换成其它物品；全部取空后可重新选物品。可以接分拣器，并在原版过滤设置中指定物品。
- 两种塔保留原版物品槽数、无人机/运输船、端口、能耗和供需模式。先在原版塔界面配置物品槽，再从市场提取对应物品。槽位有扩展库存时须先取空才能换物品。
- 对小型平台接分拣器和传送带，对两种塔测试本地无人机、星际运输船以及传送带进出。原版物流只搬运实际库存，不因平台身份生成货物。
- 平台容量不设玩法上限。扩展数量使用 BigInteger 保存，原版运输组件保留安全大小的工作缓存；原版塔容量显示“∞”，库存数字显示实际总量。缓存补充和转移不得改变库存总量。
- 已喷涂物品的数量和增产点数在缓存与扩展库存之间守恒；与背包入金规则一致，含已喷涂同类物品的平台库存拒绝存入市场，避免洗掉增产点。

## 拆除、重载与存档

- 拆除平台后，剩余物品进入交付平台页的“已拆除”记录，点击“取回库存”分批取回背包。背包满时保留剩余库存，不落地消失。拆除绑定平台会解除绑定。
- 保存/读档、F6 后核对平台实物与扩展库存总量、账户余额、绑定对象。实体、原型、坐标与仓储/物流组件归属均参与校验，回收的实体 ID 不能自动接替旧绑定。
- 旁档升级为快照 v2，兼容原有 v1 和旧 F6 交接；市场账本仍为 MarketBook v3。保存原版世界文件和对应 `.moddsv` 文件，扩展库存属于旁档。
