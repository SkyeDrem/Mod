检查日期：2026-10-26。结论：在本机代码检查与自动测试覆盖的范围内，未发现未修复的物资重复入账、免费兑换或普通物流塔被改为交付塔的问题；修复了下述三项边界缺陷。尚未完成真实 Unity 交互和其它大型 Mod / 联机环境的组合验收，不能据此保证所有 Mod 兼容。

## 已修复的问题

| 问题 | 原来的触发条件与影响 | 修复及验证 |
| --- | --- | --- |
| 固定 ID 被其它 Mod 占用时存在误处理风险 | 科技文案和交付塔逻辑按 ID 判断；即使本 Mod 注册失败，仍可能覆盖同 ID 的文案、读取其科技解锁状态，或把外来物流塔按交付塔处理 | 注册前检查整组 ID；只接受常驻模块实际注册的同一个原型对象。Finalize、研究读取、科技文案及交付库存均加归属检查。测试替换同 ID 物品、配方与科技，确认不授权交易、不改外来库存或文案 |
| 其它补丁取消拆除后交付绑定失效 | 拆除前已将物资转入暂存并标记塔已拆除，但其它 Harmony Prefix 可以随后否决实际拆除 | 拆除后检查原实体是否仍存在且身份一致，存在则恢复绑定并平衡库存。测试恢复前后物资和增产点数守恒、重复恢复不重复入账；真正拆除不恢复 |
| 空的已拆除平台记录长期累积 | 反复建拆或恢复库存后，已没有物品的旧记录仍写入旁档，增加扫描与存档开销，最终可能碰到平台数量读取上限 | 每次交付 Tick 清理无剩余库存的已拆除记录；有库存的继续保留，恢复到新槽位后才清理。测试分别覆盖保留、恢复及清理 |

## 交易和存档核查

- 各物品账户与建筑币账户独立；资源存取禁止走建筑币账户，建筑兑换仅操作建筑币账户。允许交易获利替代产线是既定玩法，不作为漏洞处理。
- 下单后端校验账户、仓位、杠杆、手续费和科技。100% 仓位预留开仓费；平仓和爆仓使用实际报价及当前平仓费，保留原持仓实际已付开仓费。
- 背包或交付库存执行时重新核数，按实际移动量结算；背包只能容纳部分物品时只扣实际收到的数量。沙土走原生沙土接口。预先检查账本边界，已喷涂的同类物品不允许直接兑换成无增产点的余额。
- 交付库存按 BigInteger 保存，原生物流槽使用安全 int 缓存；增产点随物资搬移。普通物流塔不加入交付绑定，原生槽位数量及物流模式保留。仍不允许同一普通物品重复绑定，翘曲器例外。
- F6 交接核对世界与时间，旧脚本实例不能写回覆盖新实例；各实例仅移除自身 Harmony 补丁。原版保存后导出旁档不会再搬动交付库存，避免原生快照与旁档重复记录同一批物资。异常旁档不会静默清空账户。
- 每市场最多 120 个报价点、10 条操作记录，界面显示最近 6 条。累计字段独立保存，不随历史淘汰而清零。停用市场不推进行情，也不补算停用期间行情。

## 兼容性边界

| 环境 | 当前结论 |
| --- | --- |
| 当前 FXDSP Profile | 扫描到 ScriptEngine、DSPModSave、LDBTool、ConfigurationManager 与本 Mod 常驻模块；本次对本机引用编译并验证部署，不等于已完成游戏内联测 |
| 原型 ID 冲突或 LDBTool 手工重映射 | 仍使用科技 1951、7701～7705、7801～7806 和物品/配方 11702、11703。冲突会报错，归属检查使本 Mod 不接管外来原型；不支持自动协商新 ID。部分注册或其它 Mod 的错误仍可能影响启动，需结合日志处理 |
| 改造物流塔的 Mod | 普通物流塔补丁有归属边界，但若其它 Mod 改变交付塔 storage 数组、搬运接口、容量语义、实体生命周期或使用不一致的线程锁，仍须联测。取消拆除这一种交互已有回归覆盖，不能推广为所有物流扩展兼容 |
| 改配方或大型内容扩展 | 建筑币价为原版配方的固定计算表，不会随其它 Mod 的配方、产量自动重算；因此可能出现经济套利或不合适的价格。新增建筑没有价格时不列入兑换，不使用免费或随意的默认价格。资源目录也不是自动覆盖任意新增 ID 的适配层 |
| 联机，例如 Nebula | 当前没有同步交易、随机行情、账户和扩展交付库存的网络协议，尚不支持联机玩法，未在联机环境测试 |
| 热键与原版保存 | F8 可配置；与其它 Mod 的相同热键需自行错开。保护旁档的保存拦截仅在本 Mod 未正确接入当前档时触发，此时需带着本 Mod 重新读档，不应直接绕过保护保存 |
| 极端规模 | 当前读取保护限制旁档 4 MiB、最多 256 个账户及 8192 条交付平台记录。原版目录为 104 个可选行情和 71 个兑换项；清理空拆除记录避免通常的建拆累积，但未验证数千座交付塔或大量新增品种的超大档。BigInteger 库存无玩法容量上限不等于内存和存档无限 |

Debug / Release 均构建核心与常驻模块，零警告零错误。原版行内图标解析器通过 24 个标记检查；实际编译导入器通过 80×80 图集尺寸、透明及细等级笔画检查。12 个源图标检查通过，图集哈希未变。价格生成检查通过：175 物品、162 配方、71 兑换价，传送带仍为向上取整后的 6。

## 游戏验收步骤

1. 完整重启 FXDSP Profile；本次常驻模块也更新了，首次加载 0.18.0 需要重启，之后单改交易脚本仍可 F6。原有 0.17.x 存档格式未变，无需为本次改动开新档。
2. 打开建筑币兑换，确认五个入口整段对应色、没有多余颜色字；切换建筑，检查大图标与名称居中、比例正确。
3. 对一项建筑分别兑换与回收；背包不足以装下全部兑换数量时核对实际数量及双向手续费。分别测试尚未解锁和已解锁等级。
4. 两种交付塔各设置一种物品，存取后让传送带、分拣器和物流运输继续工作，核对库存与绑定；普通物流塔不应出现无限容量或查重拦截。
5. 拆除有库存的交付塔，再在另一交付塔设置同种物品；核对旧库存只恢复一次。保存读档、再 F6，核对余额、持仓、交付库存和研究进度。
6. 若准备加入大型物流或内容 Mod，先复制测试档，按上述完整流程组合验收；联机须先实现专门适配。
